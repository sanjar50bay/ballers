## Ключевой новый сценарий
Четыре изолированных аккаунта: OWNER, MANAGER, MEMBER, гость, который владеет другим сообществом. Серверные тесты проверяют отсутствие полномочий вне конкретного сообщества, отказ в изменении чужого участия/правил/составов/запуске, отказ самоповышению роли, отсутствие анонимного доступа к личным RPC. Наличие другого собственного сообщества не даёт прав на этот игровой день.

Последнее место → заявка гостя без «Иду» → принятие ровно один раз → принятие следующего в резерв → отмена первого → одно предложение места следующему → отдельное подтверждение самим игроком → один занятый слот. Более поздняя заявка не крадёт уже предложенное место. Повторное принятие/подтверждение не создаёт дублей. Принятие, резерв и предложение правильно видны на главной.

Браузер подтверждает различие доступных инструментов OWNER/MANAGER/MEMBER, общий каталог чужих авторов, переход из личных сообществ, ближайшую игру до записи, отсутствие дублирующего поиска в пустом состоянии, пустой выбранный город без ложного предложения входа, ошибку с повтором загрузки без ложного пустого списка. RU/KK-меню и главная проверены при ширине 320px; снимки `reliability-home-320.png`, `reliability-menu-kk-320.png`.

Регистрация отдельно проверена на новом пользователе, повторной отправке/гонке, медленном ответе, сохранённом INSERT с потерянным ответом, ошибке первичного чтения, восстановлении, повторном входе и сохранении приглашения. Google-экран и настоящее состояние OAuth-сессии после провайдера локальный стенд не воспроизводит.

## Что исправлено, а что ещё нуждается в проверке
Подтверждённый дефект: ожидающая заявка гостя без строки участника/членства пропадала из `ballers_home()`. Исправлено SQL007 без добавления автоматического членства/участия. Общая функция каталога уже была глобальной в 006; 007 задаёт её целиком повторно, с явными grants и без фильтра автора. Точную причину отличающегося каталога в действующем Supabase без его диагностики не установили.

Проверки доступа уже существовали до 028; факт серверного обхода не установлен. Исправлены понятность контекста, скрытие недоступной OWNER-кнопки и read-only отображение ролей для обычного игрока. Просмотр общих результатов/составов не является разрешением их менять.

Не проверены на живом проекте: реальные Google OAuth, Realtime и сетевые особенности Supabase, RLS/данные именно рабочего проекта, push/фон, Safari и реальное касание пальцем. После установки нужен короткий прогон организатор + два игрока на телефонах. Существующие аккаунты ради этого не удалять.

Второй пакет LIVE/landing/videos/крупная тактика/режим карточки Baller ID пока не реализован. Результаты по-прежнему только подтверждённые, тестовые отдельно. Автоматический показ карточки по прежнему cooldown пока сохранён.
