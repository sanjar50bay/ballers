# BALLERS 0.2.4 — срочный патч первого создания профиля

## Что подтверждено
На старой сборке 0.2.3 воспроизведено: профиль успешно записан, но главная использует сохранённое `profile: null` и возвращает на onboarding. Повторный INSERT вызывает `player_profiles_user_id_key`. Это не доказательство всех причин ожидания на конкретном телефоне: реальных сетевых логов пользователя нет.

## Исправлено
- При открытии анкеты проверяется собственный существующий профиль. Если он уже есть, открывается главная, новая запись не создаётся.
- Перед записью выполняется повторная проверка. Если другой таб успел создать профиль или ответ на INSERT потерялся, проверяется сохранённая собственная строка. Ошибка уникальности сама по себе не считается успехом.
- Существующий профиль, имя и Baller ID не перезаписываются анкетой; уникальное ограничение БД сохранено.
- Синхронная блокировка повторной отправки, отключение формы при сохранении, try/catch/finally, 15-секундные пределы отдельных сетевых операций. Последовательность из нескольких проверок может длиться дольше 15 секунд; при проблеме предлагается явный повтор. Неопределённая запись автоматически не повторяется.
- После подтверждённого сохранения выполняется полноценный переход на свежую главную (`location.replace`), сбрасывающий устаревший AppState. Нет необходимости вручную выходить и входить.
- Сетевой сбой чтения не считается отсутствием профиля. Ошибка заметна и получает фокус; введённые поля остаются при ошибке отправки. Колокольчик не перекрывает onboarding/приглашение.
- Регистрация по приглашению использует ту же защиту и сохраняет целевой маршрут. Серверное принятие приглашения и проверки прав не обходятся.

## Установка поверх работающей 0.2.3
**Новой SQL-миграции нет. В Supabase ничего не выполнять. Не повторять 001–004 или baseline.** Нужна уже установленная 004 из 0.2.3.

1. Сохрани копию текущего проекта. Останови сервер Ctrl+C.
2. Распакуй ZIP. Содержимое папки `ballers-alpha-0.2.4` скопируй поверх текущей подключённой к GitHub папки проекта. Не вкладывай новую папку внутрь старой. Не удаляй `.git`, `.env.local`, свои настройки. Архив не содержит ключей.
3. В PowerShell в текущем проекте:

```powershell
npm ci
npm run build
npm run start
```

4. На localhost проверь существующий аккаунт. Для нового аккаунта нужен отдельный вход Google, которого ещё нет в профилях, а не удаление старого профиля. localhost и опубликованный сайт имеют раздельное хранилище сессии.
5. После проверки останови сервер, просмотри отправляемые файлы:

```powershell
git status
git add .
git diff --cached --name-only
```

Если видны `.env.local`, настоящие секреты или приватные ключи — не делай commit. `.env.example` допустим: там только пустые публичные настройки.

```powershell
git commit -m "Fix first profile onboarding and safe registration retries"
git push origin main
```

6. Дождись Netlify Published, открой https://ballerrs.netlify.app. Настройки Netlify, Google OAuth и Supabase key менять не нужно. Если открыт старый экран — обнови вкладку.

## Проверка на реальном телефоне после публикации
Новый тестировщик входит своим Google → заполняет анкету один раз → попадает на главную. После обновления/повторного входа тот же Baller ID и профиль; анкета заново не появляется. Проверить Safari и браузер, где пользователи получили ошибку. Затем проверить вход новым человеком по действующей ссылке приглашения: профиль создаётся один раз, открывается нужное сообщество/игра. Не удаляй существующие профили ради тестирования.

Существующие пользователи с уже созданным профилем должны открыть его без новой регистрации. При новой ошибке нужны точный текст, время, браузер и маршрут без токенов/ключей. Скриншоты и логи не должны раскрывать секреты.

## Границы
Это патч регистрации, не турнирный модуль и не новая анимация карточек. Реальный Google OAuth и живой Supabase агентом не проверены. Отчёт локальных проверок: `VALIDATION_0024.md`.
