# Проверка патча регистрации 0.2.4-alpha

## Воспроизведение до исправления
На собранной 0.2.3 новый изолированный пользователь сначала открывает главную (профиля нет), переходит на onboarding, создаёт профиль. Реальный INSERT в PGlite успешен. Клиентский переход использует прежний AppState и возвращает на onboarding. Повторная отправка получает реальную ошибку уникального user_id. Проверка воспроизведения прошла до замены исходников; отчёт `reports-0024/reproduction.txt`.

## После исправления
- Production build успешен.
- Линтер: 0 ошибок, 6 прежних предупреждений на старых страницах.
- 129 прежних SQL/структурных проверок пройдены.
- 17 браузерных проверок регистрации пройдены:
  - первый профиль и отсутствие возврата на анкету;
  - повторные синхронные submit-события (один INSERT);
  - медленный ответ записи;
  - потерянный ответ после успешной записи;
  - ответ записи позже 15-секундного таймаута;
  - создание той же личности другой вкладкой между чтением и записью;
  - существующий профиль без перезаписи имени и Baller ID;
  - сохранение сессии/Baller ID после обновления страницы;
  - ошибка первоначального чтения и явный повтор;
  - отказ записи не считается успехом, кнопки восстанавливаются;
  - отсутствие сессии — отсутствие INSERT;
  - некорректный год и одинаковые позиции не отправляются;
  - запись успешна, но ответ и последующая проверка недоступны: ручной повтор читает существующий профиль, не отправляет второй INSERT;
  - посторонний unique conflict без собственного профиля не считается успехом;
  - ширина 320px без горизонтального переполнения и без перекрывающего анкету колокольчика;
  - новый пользователь по приглашению, включая потерянный ответ INSERT: целевое сообщество сохранено, одно членство MEMBER, одно расходование ссылки;
  - существующий пользователь по приглашению: без нового профиля, одно членство и один расход ссылки.
- 23 прежние браузерные проверки игрового цикла/навигации пройдены после патча.

Названия отдельных утверждений в отчёте могут объединять несколько действий. Суммарно браузерный прогон — 40 проверок, включая 17 регистрационных и 23 прежних.

## Визуальный просмотр
Индивидуально просмотрены четыре финальных снимка `hotfix-registration-*.png`: анкета, ошибка первоначального чтения с повтором, ошибка отправки с сохранёнными полями и переход на главную нового пользователя. Размер 390×844 (анкета — полный снимок страницы). На ошибке отправки фокус/прокрутка переводят к пояснению; колокольчик не закрывает поля. Неоновый стиль сохранён. Старые игровые экраны проверены прежним браузерным набором.

## Что не проверено
Это локальный Chromium с настоящими PostgreSQL/PGlite-функциями и RLS, но синтетической OAuth-сессией и имитацией HTTP/PostgREST. Идентификация через реальные серверы Google, действующие Supabase/PostgREST, реальные Safari/iOS и production Netlify этим прогоном не проверялись. Страница назначения приглашения в регистрационном тесте заменена простой тестовой страницей: проверены путь перехода и настоящая серверная запись членства, не её внешний вид. Полный прежний игровой браузерный набор проверяет игровые экраны отдельно.

Зависимости не обновлялись; прежние ограничения безопасности alpha и dev-аудита не объявляются устранёнными патчем. Таблицы, миграции и ограничения не менялись. После публикации обязателен первый вход нового реального Google-пользователя на телефоне и проверка приглашения; порядок в UPDATE_0024.md.

## Повтор локальных тестов
`npm test`, `npm run build`, `npm run lint`.

Для браузерных тестов нужен Playwright и установленный Chromium. Модуль и исполняемый файл можно указать через PLAYWRIGHT_MODULE и CHROMIUM_PATH. Сервер должен быть собран с фиктивными NEXT_PUBLIC_SUPABASE_URL=https://example.supabase.co и публичным тестовым ключом, затем запущен на 127.0.0.1:3012 (или TEST_BASE_URL). Это не настройки для публикации настоящего сайта. Тест перехватывает транспорт к example.supabase.co, рабочая БД не используется.

`npm run test:registration:browser` — регистрация. `node tests/browser.test.mjs` — игровой набор. Текстовые отчёты сохранены в reports-0024.
