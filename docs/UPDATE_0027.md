# BALLERS 0.2.7 — игровой день, заявки и тактика

## Для действующей 0.2.6
Нужна **только новая миграция 006**, после уже установленных 001–005. Рабочая Git-папка остаётся `Музыка\ballers-alpha-0.2.2`, независимо от номера версии приложения. Не создавать новый Git-репозиторий и не переносить ключи в чат.

## Что изменено
1. **Каталог.** Все города по умолчанию, точное количество результатов, номер/число страниц, по 24 записи. SQL каталога целиком заменён: агрегаты используют `count(1)`, включая поиск сообществ. В каталоге команд — постоянные команды, а не временные Blue/Red/Yellow игрового дня. В каталоге игроков — профили с аккаунтом; синтетические TEST-игроки исключены. Отсутствие аккаунта/профиля и фильтр города не означают неисправность пагинации. На стенде проверены 60 профилей / 3 страницы и 27 команд / 2 страницы. Точная причина прежнего неполного списка на рабочем сайте без его данных не установлена.
2. **Итоги игрового дня** в игровом центре: таблица команд (И/В/Н/П, мячи, очки), бомбардиры с голами/ассистами/сейвами, протоколы со счётом, статусом, снимком составов и событиями. Только подтверждённые результаты входят в таблицу/бомбардиров; тестовые матчи отдельно. В протоколе видны отменённые события, но они не учитываются в показателях. Автогол не становится личным голом. Победа 3, ничья 1, поражение 0; сортировка очки → разница → забитые → имя. Подтверждения капитанов/споры доступны по ссылке в прежний блок результатов.
3. **Заявка на игровой день.** По умолчанию — подтверждение организатором. Самостоятельный отклик не занимает место и не создаёт подтверждённого участника. Организатор получает запрос в колокольчике и принимает/отклоняет; заявитель видит решение. При принятии повторно проверяется вместимость, далее действует очередь с сохранением её порядка. Повторное принятие не создаёт дубль. Ожидающую заявку можно отозвать. Отмена организатором обозначается отдельно от собственного отказа. Завершение дня закрывает ожидающие заявки, не закрывая подтверждения результатов матчей.
4. **Режим записи.** В игровом центре организатор может явно выбрать «Свободная запись». Это не принимает старые ожидающие заявки автоматически. Уже записанные игроки не удаляются. Прямое приглашение от организатора / выданная им гостевая ссылка считается разрешением на участие: повторное одобрение не требуется, но ограничение мест и очередь сохраняются.
5. **Верхний плюс.** Меню: игровой день, постоянная команда, сообщество. Турнир и «У меня есть арена» показаны как «Скоро» без неработающих форм. Название «сообщество» пока не менялось.
6. **Матч.** Добавлены жёлтая/красная карточки как события и подпись «Кто ведёт счёт матча». Ассист записывается с голом, не отдельным дублирующим событием. Карточки не меняют счёт и пока не удаляют игрока с поля автоматически.
7. **Звук и live-индикатор.** После явного включения звука — синтезированный свисток начала/окончания, тоны гола/ассиста/сейва/карточек. Исторические события при первом открытии не проигрываются заново. Звук действует на открытом экране, зависит от разрешений браузера; это не push и не фоновый будильник. Мигающий мяч показывает live; при reduced motion анимация отключена.
8. **Тактическая доска 5×5** на странице постоянной команды: ответственный выбирает до пяти подтверждённых игроков, двигает мышью/пальцем/стрелками и сохраняет. Остальные смотрят. Соперник обозначен условными фигурками. Версия защищает от перезаписи более новой расстановки. Это не изменение заявки/состава и не связь постоянной команды с матчем.
9. **RU/Қазақша**, существующая регистрация, карточка игрока, игры и команды сохранены. Next.js зафиксирован на 16.4.3; зависимости проверены через npm audit.

## Установка — сначала один шаг
**До SQL:** сохраните резервную копию базы и рабочей папки; убедитесь, что можете восстановиться. Не удаляйте аккаунты для тестирования — используйте новый тестовый Google-аккаунт.

В SQL Editor проекта **BALLERS Test** (не в новом Astana Amateur Ballers) создайте новый пустой запрос. Вставьте **весь** `supabase/migrations/20261027_006_day_results_requests.sql`, включая комментарии, `BEGIN;` и `COMMIT;`. Run один раз. Первая строка-комментарий должна оставаться с `--`. Не копируйте SQL через редактор, который съедает символы; отдельный SQL-файл идентичен файлу в ZIP. При ошибке остановитесь и пришлите текст, не продолжайте с середины и не убирайте проверки истории. Повторное применение 006 намеренно блокируется.

Проверка после Success:
```sql
SELECT version FROM public.ballers_migration_history ORDER BY version;
```
В списке должна появиться `20261027_006`. Каталог проверяйте на сайте под авторизованным пользователем.

### Затем файлы и публикация
1. Распакуйте ZIP отдельно, в `Музыка\ballers-alpha-0.2.7`.
2. В этой новой папке откройте PowerShell. Запустите:
```powershell
powershell -ExecutionPolicy Bypass -File .\UPDATE_EXISTING_PROJECT.ps1
```
Скрипт проверит существование `.git` у старого проекта, скопирует исходники без удаления и сохранит `.git`, `.env*`, `.netlify`. Он не устанавливает SQL, не публикует и не делает commit. При ошибке копирования остановитесь.
3. Перейдите именно в прежнюю Git-папку:
```powershell
cd "$env:USERPROFILE\Music\ballers-alpha-0.2.2"
npm ci
npm audit
npm run build
git status --short
```
При ошибке сборки не публикуйте. Не запускайте `npm audit fix --force` автоматически.
4. После успешной сборки:
```powershell
git add .
git diff --cached --name-only -- ".env*" ".netlify"
```
Если последняя команда показывает `.env.local`, секреты или `.netlify`, остановитесь. `.env.example` — только шаблон, без ключей. Проверьте изменения и затем:
```powershell
git commit -m "Release 0.2.7: day results, approval requests and tactics"
git push origin main
```
5. В Netlify дождитесь успешного опубликованного deploy именно этого commit. Изменения базы сами по себе не публикуют новую версию сайта.

## Проверка после публикации — два отдельных аккаунта
- Новый игрок: Google → анкета RU/KK → один Baller ID → повторный вход без анкеты. Существующих пользователей не удалять.
- В «Найти» выбрать все города, проверить следующую страницу и поиск по Baller ID / названию, включая Wednesday.
- Игрок открывает публичный день → подаёт заявку. У организатора появляется запрос; до принятия число «Иду» не растёт.
- Принятие/отклонение, отзыв заявки, заполненная игра → очередь, отмена организатором → сообщение игроку.
- Личный инвайт организатора сохраняет приглашение и вместимость без второй заявки.
- Сыграть тестовый матч, записать гол с ассистом/сейв/карточки, отменить событие, завершить/подтвердить. Проверить протокол, таблицу и отделение тестов от реальных показателей.
- Ответственный сохраняет доску; другой игрок видит, но не редактирует. Проверить реальный телефон: touch, звук после нажатия, 320px.

## Ограничения и безопасный откат
- Реальный Google OAuth, Supabase, Netlify и телефоны не проверялись автоматически: стенд локальный, транспорт и OAuth имитированы.
- Вкладки обновляются действиями/периодическими запросами; это не системные push. Фоновая вкладка может обновиться позже.
- Редактирование названия/удаление команды и передача капитанства ещё не добавлены. Нет турниров/бронирования арен/Referee ID/ленты.
- После 006 **старый интерфейс 0.2.6 не умеет обрабатывать новые заявки**. Нельзя просто откатить UI и оставить режим APPROVAL без контроля. При проблеме оставьте проверенный интерфейс или временно переключите конкретные открытые дни в AUTO осознанно; для полного отката базы используйте проверенную резервную копию с учётом новых записей. Не удаляйте новые таблицы/историю вручную.
