ПУБЛИЧНЫЙ КАТАЛОГ — ПОРЯДОК ВЫПУСКА

1. До публикации интерфейса применить в Supabase миграцию:
   supabase/migrations/20261125_015_public_open_games.sql
   Она добавляет отдельную функцию чтения публичных карточек для anon и authenticated.
   Существующие разрешения таблиц, запись в игру и членство не меняются.

2. Проверить: SELECT public.ballers_public_open_games('Astana',3);
   Пустой массив нормален, если нет игр с включённым публичным добором.
   Не открывать тестовые дни ради наполнения каталога.

3. Проверить тестовую версию без входа: главная → город → Посмотреть игры →
   выбрать игру → вход → при необходимости создать профиль → вернуться к игре.
   Вход не должен автоматически отправлять заявку или записывать игрока.

4. После успешных проверок объединить PR и проверить основной сайт.
   Для Google/email возвращаем пользователя на /open-games?game=<uuid>.
   Также сохраняем выбранную игру на этом устройстве: если провайдер вернул
   пользователя на главную, профиль/регистрация восстановят переход.

Ограничения этого этапа:
- Подписка «Сообщить о новых играх» пока в плане, кнопки нет.
- Цены не показываются: у игры ещё нет соответствующего поля. Это не означает,
  что игра бесплатная.
- Нельзя определить ручной тестовый день только по намерению создателя.
  Его публичный добор должен оставаться выключенным. Игры с is_test-матчами
  или системными BALLERS_TEST-игроками дополнительно исключаются из публичной выдачи.
- Публичный каталог выдаёт ближайшие 24 игры с фильтром города; функция ограничена
  максимумом 100. Полная пагинация и подписки — отдельный этап масштабирования.
- Ошибка API показывается как ошибка с повторной загрузкой, а не «игр нет».
- Для отката интерфейса достаточно вернуть предыдущий деплой: новый RPC не меняет
  поведение старого приложения и не требует отката данных.
