# Проверка 0.2.7-alpha

## Среда и границы
Node 24, Next.js 16.4.3 production-сборка, изолированный PostgreSQL (PGlite), Chromium/Playwright. Применена цепочка baseline + миграции 001–006 только в изолированных тестовых БД. RLS, права, RPC и транзакции настоящие; транспорт HTTP и сессии OAuth имитируются. Не использовались живой Supabase, реальные аккаунты, Netlify или Google OAuth. Ничего не опубликовано автоматически. Звук проверен через настоящий AudioContext в Chromium; iPhone/Android требуют отдельной проверки.

## Критические сценарии
- APPROVAL по умолчанию: самостоятельная запись участника/гостя создаёт одну заявку, не строку «Иду». Дубли отправки/решений не умножают участников.
- Принятие последнего места, принятие следующего в очередь, отозванная/отклонённая заявка, отдельная отмена организатором, закрытие дня, сохранение незавершённых подтверждений матчей.
- AUTO включается только организатором, не принимает прежние заявки автоматически. Явный инвайт допускает без второй заявки, но не обходит очередь.
- Чужой пользователь не принимает заявки, не меняет режим и не вызывает внутренний attendance-bypass. Прямые записи в новые таблицы закрыты. Anon не читает заявки и не сохраняет доску.
- Каталог: SQL 55 профилей (24/24/7), 26 команд (24/2), поиск Wednesday; браузер 60 профилей и 27 команд. Проверено отсутствие пропуска/дублирования ID между страницами и фильтр города. Это не доказательство точной причины старого инцидента в живой базе.
- Доска: только ACTIVE-игроки, до пяти, без дублей, координаты в поле; чужой капитан не редактирует; устаревшая версия отвергается. Мышь/клавиатура, сохранение, перезагрузка, сброс черновика.
- Итоги: VERIFIED выбранного типа; PENDING/DISPUTED не дают очков; voided не учитываются; автогол не становится личным голом; ассист — только у гола. Жёлтая/красная валидируются по оператору и снимку состава, не меняют счёт, отмена сохраняет аудит.
- Звук: включение по жесту, GOAL+assist, старт/финиш через настоящий AudioContext, повторный poll не дублирует тоны. Live-мяч с отключением движения при reduced motion. Нет гарантии фонового воспроизведения/системных push.
- Регистрация RU и KK: новый/существующий профиль, медленный ответ, потерянный ответ INSERT, timeout, race, повторный вход, отказ записи, неверный год/позиции, приглашение после регистрации, 320px. Не утверждается проверка настоящего Google OAuth.

## Как повторить браузерные проверки
1. `npm ci`; установить Playwright/Chromium в отдельной тестовой среде (в архиве их бинарников нет).
2. Собрать и запустить с фиктивными тестовыми значениями URL/публичного ключа; не подставлять production secrets в фикстуры.
3. Передать `TEST_BASE_URL`, при необходимости `PLAYWRIGHT_MODULE` (абсолютный путь к модулю) и `CHROMIUM_PATH` (бинарник).
4. Запустить перечисленные `.mjs`. Все запросы к `https://example.supabase.co` перехватываются локальным стендом.
5. Для регистрации отдельно выполнить RU/KK; `TEST_LOCALE` задаётся способом вашей оболочки, не копируйте синтаксис Bash в PowerShell.
