# BALLERS 0.2.10 — доверяем ведущему

Это полная версия поверх 0.2.9. Единственное новое функциональное изменение — режим учёта результатов и необходимые для него настройки/исправления/журнал. Все изменения 0.2.9 сохранены; их отдельно устанавливать перед этим архивом не нужно.

## Как теперь работает
- По умолчанию новые матчи работают в режиме «Доверяем ведущему — сразу в статистику». Назначенный оператор или организатор завершает матч: результат сразу входит в таблицу дня, список бомбардиров и личную статистику. Нет дополнительного согласования капитанами.
- Завершение по лимиту голов и завершение по таймеру через существующий клиентский механизм работают так же. Пока матч LIVE/PAUSED, итоговая таблица его не считает: это не предварительная LIVE-таблица.
- На игровых экранах результат помечен «Учтён ведущим». Это не подделанные галочки подтверждения капитанов: поля подтверждений не заполняются за них.
- Строгий режим доступен организатору в «Учёт результатов» → «Режим для новых матчей». В нём сохраняются прежние подтверждения обоих капитанов и споры. Режим фиксируется при старте каждого матча, смена настройки действует только на следующие матчи.
- После завершения доверенного матча только организатор может отменить ошибочное событие либо добавить пропущенное (гол, автогол, сейв, жёлтая/красная). Требуется причина, минимум 5 символов. Счёт/статистика пересчитываются сразу; запись отменённого события остаётся в протоколе.
- «История изменений результата» показывает автора, время, действие, причину и счёт после действия. Доступна тем, кто имеет право видеть сам игровой день; посторонний доступа не получает.
- Исправления результата не переписывают уже выполненную ротацию и историю следующих составов. Это сознательная защита истории, а не повторное проведение игрового дня.
- Тестовые матчи по-прежнему отдельно от реальных. Доверенный режим не делает TEST-матчи реальными.

## Старые матчи
Миграция НЕ пересчитывает и не переутверждает их автоматически. Старые завершённые и уже начатые матчи сохраняют прежний режим капитанских подтверждений. Для законченного результата со статусом «Ждёт подтверждений» организатор может явно нажать «Учесть без подтверждений» и указать причину. Спорные результаты этим действием не обходятся: сохраняется прежнее решение спора.

Внимание: после применения SQL новые матчи будут по умолчанию доверенными даже до публикации новых файлов. Обновление лучше выполнить между играми, затем сразу опубликовать сайт.

## 1. Сначала SQL — один раз
1. Сохраните резервную копию рабочей базы и рабочей папки, убедитесь в возможности восстановления.
2. В Supabase выберите **BALLERS Test**, ref `cupgzvetwptqavxzbccm`, где уже установлены 001–007. Не другой проект Astana Amateur Ballers.
3. В новом пустом запросе SQL Editor выполните целиком файл **`supabase/migrations/20261029_008_trusted_results.sql`**. Отдельный SQL рядом с ZIP идентичен файлу внутри архива. Не запускайте прежние миграции и baseline повторно. Не обрезайте BEGIN/COMMIT и не снимайте проверки истории. При ошибке остановитесь.
4. После Success:
```sql
SELECT version FROM public.ballers_migration_history ORDER BY version;
```
Должна добавиться `20261029_008`. Миграция не удаляет пользователей, команды, события или историю, не отключает RLS. Она не публикует сайт.

## 2. Затем файлы
Распакуйте ZIP отдельно в `Музыка\ballers-alpha-0.2.10`. PowerShell в новой распакованной папке:
```powershell
powershell -ExecutionPolicy Bypass -File .\UPDATE_EXISTING_PROJECT.ps1
```
Скрипт сохраняет `.git`, `.env*`, `.netlify` в прежней рабочей папке. Затем все команды — в **старой Git-папке 0.2.2**:
```powershell
cd "$env:USERPROFILE\Music\ballers-alpha-0.2.2"
npm ci
npm run build
npm audit
```
При ошибке остановитесь, не делайте push и не используйте audit fix --force автоматически.
```powershell
git status --short
git check-ignore .env.local
git add .
git diff --cached --name-only -- ".env*" ".netlify"
git diff --cached --stat
```
.env.local должен игнорироваться, последний список приватных файлов должен быть пустым. При попадании ключей не продолжайте.
```powershell
git commit -m "Release 0.2.10: trusted operator results and correction history"
git push origin main
```
Дождитесь успешного deploy соответствующего commit в Netlify. Ни подготовка ZIP, ни локальная сборка сами сайт не обновляют.

## 3. Проверка после публикации
- Новый матч обычного дня: назначенный ведущий записывает гол → завершает → сразу появляются очки/бомбардир. Капитанских кнопок подтверждения для него нет.
- Организатор исправляет гол с причиной → счёт и статистика меняются, история видна; обычный игрок не получает эти кнопки.
- Строгий режим → следующий матч по-прежнему требует капитанов. Уже начатый матч не переключается задним числом.
- Тестовые результаты остаются на тестовой вкладке и не влияют на карьеру.
- RU/Қазақша, реальный телефон. Новые функции при подготовке проверялись локально, а не в действующем Supabase/Google OAuth.
