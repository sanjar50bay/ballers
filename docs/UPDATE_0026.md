# BALLERS 0.2.6 — найти людей и собрать команду

## Для какой установки
Для действующей 0.2.4 или 0.2.5 с уже применёнными миграциями 001–004. **0.2.5 отдельно устанавливать не нужно:** этот пакет включает RU/Қазақша, неоновую карточку и защиты регистрации.

Новая миграция: `supabase/migrations/20261024_005_directory_teams.sql`. Она добавляет новые таблицы и RPC; существующие аккаунты, Baller ID, сообщества, игровые дни, матчи и результаты не удаляет. Старый игровой Team Builder и постоянные команды используют разные API.

## Что готово
- Нижняя навигация: Главная · Игра · Найти · Профиль. Свои сообщества остаются на главной и по прежнему адресу `/communities`.
- Раздел «Найти»: игроки, постоянные команды, сообщества, входящие запросы. Город, поиск по имени/нику/Baller ID, фильтр ищущих команду, страницы по 24 результата.
- По умолчанию текущий город игрока; можно выбрать все города. Астана — первый запуск. Алматы/Караганда помечены «Скоро», но создавать профиль и команду там уже можно. Для других городов есть ввод названия. Геолокация не запрашивается и город автоматически не меняется.
- «Твой футбол»: текущий город, «Ищу команду / Есть команда / Хочу играть», независимая готовность к приглашениям на игры. Новичку без игр и сообществ предлагается выбрать эти настройки, но регистрация не блокируется.
- Один профиль и Baller ID при переезде. Меняется место поиска, а не история. Старые географические строки не перезаписываются миграцией; известные варианты Astana/Астана и т.п. сопоставляются при поиске.
- Постоянная команда: название, город, описание, ответственный и подтверждённый состав. Создание защищено от двойного нажатия и повтора запроса.
- Капитан ищет игроков по всем городам, выбирает до 30 и отправляет приглашения. Игрок принимает или отклоняет. Самостоятельная заявка по командной ссылке требует подтверждения капитаном. Ссылка не добавляет в состав автоматически.
- Повторные командные действия после потерянного ответа защищены идентификатором операции в пределах текущей попытки. Принятое решение не разворачивается повтором; повторное приглашение после успешной предыдущей операции — отдельное действие.
- Общая ссылка `/teams/<id>`; после входа/создания профиля пользователь возвращается к команде. Для команды не создаётся второй аккаунт.
- Одна команда может состоять в нескольких сообществах. Капитан отправляет заявку; организатор/менеджер сообщества подтверждает. Это не выдаёт права организатора и не добавляет всех игроков автоматически в индивидуальное членство сообщества или игровой день.
- Командные приглашения/заявки доступны через верхний колокольчик → «Командные запросы» и через раздел «Найти». Ответ убирает запрос из актуального списка. Обновление при фокусе/с интервалом до 10 секунд на открытом сайте; это не push-уведомления.
- Публичный профиль игрока: настоящая подтверждённая статистика, статус и команды. Убраны вымышленные 500 рейтинга и статические нули старой публичной страницы. Новый API каталога выдаёт явный набор публичных полей; не выдаёт email, телефон, год рождения или user_id. Старые API игрового центра не переписывались.
- RU/Қазақша на всех 22 страницах, чёрно-неоновая палитра, мобильные вкладки без скрытого бокового скролла.

## Что пока не сделано — важно
- Постоянная команда ещё не привязана к временным командам игровых дней. Поэтому победы/поражения постоянной команды не выдумываются и не считаются по совпадению названий. История игроков работает по-прежнему. Привязка команд к матчам и запуск игры постоянными составами — следующий этап.
- Нет турниров, календарей чемпионата, подтверждённых ролей тренера/судьи, Referee ID, каталога арен, ленты или продвижения профиля. Для них не добавлены пустые разделы.
- Нет редактирования/удаления команды, передачи капитанства или назначения второго ответственного. Автор команды — её единственный ответственный в этой версии; он не может случайно покинуть собственную команду.
- «Есть команда» — заявленный статус поиска, не доказательство членства. Официальный состав формируется только подтверждёнными приглашениями/заявками. Игрок может иметь несколько команд.
- Нет мгновенной общей подписки на все изменения: используются обновление страницы, действия и периодические запросы. После приёма приглашения на другом устройстве может понадобиться обновить открытый состав.
- Реальный Google OAuth, живой Supabase и телефоны участников проверяются отдельно после публикации. Локальные тесты используют настоящую изолированную SQL-базу и имитированный транспорт.

## Порядок установки — не менять папки местами

### 1. Сначала база
Сохрани резервную копию действующего проекта/БД. В SQL Editor того же **BALLERS Test** создай **новый пустой запрос** и вставь целиком файл `20261024_005_directory_teams.sql` — от первой строки-комментария до `COMMIT;` включительно. Нажми Run один раз.

**Baseline и 001–004 повторно не запускать. Не удалять старые таблицы.** При ошибке остановись и пришли текст ошибки. Не вырезай отдельные строки/команды из середины. Повтор 005 специально блокируется до изменения схемы.

Пока используется старый сайт, новые таблицы ему не мешают. Если опубликовать код без 005, каталог покажет понятное сообщение о нужной миграции, но не станет удалять профиль.

### 2. Затем исходники
Распакуй `ballers-alpha-0.2.6` рядом со старой Git-папкой `Музыка\ballers-alpha-0.2.2`. Открой PowerShell **в новой распакованной папке**:

```powershell
powershell -ExecutionPolicy Bypass -File .\UPDATE_EXISTING_PROJECT.ps1
```

Скрипт копирует исходники в прежнюю Git-папку, не переносит node_modules/.next/.git/.netlify/.env и ничего не удаляет. Он не запускает SQL, commit или push. Git-папка остаётся с именем `ballers-alpha-0.2.2`; переименовывать её не нужно.

### 3. Проверка и публикация
Открой PowerShell **в старой Git-папке `ballers-alpha-0.2.2`**:

```powershell
npm ci
npm run build
git status
```

Проверь, что секретные и сгенерированные файлы не попали в изменения. Затем:

```powershell
git add .
git diff --cached --name-only
```

Если список безопасный:

```powershell
git commit -m "Add city discovery and persistent teams"
git push origin main
```

Дождись нового **Published** в Netlify. Настройки Google, публичные Supabase-переменные, Next Runtime и secrets scanning не менять. Код не содержит service_role и не требует секретного ключа в браузере.

## Проверка вдвоём после публикации
1. Новый пользователь → Google → профиль с городом → главная → «Твой футбол». Не должно быть duplicate key и зависания.
2. Найди друга по Baller ID. Создай команду и пригласи его. До принятия он в ожидающих, после — в составе.
3. Друг открывает ссылку без входа → входит/создаёт профиль → возвращается к команде → подаёт заявку. Без решения капитана состава не меняет.
4. Ответственный подаёт заявку в два сообщества. Их организатор принимает. Это та же команда, а не две копии.
5. Меняем город игрока → Baller ID, команды и карьера сохраняются. Открытые игры фильтруются новым городом; другой город можно выбрать вручную.
6. Проверить оба языка, колокольчик, отказ/отзыв, телефон 320–390 px, старый игровой день и его результаты. Казахские формулировки желательно проверить носителем языка.
