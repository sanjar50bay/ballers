# Обновление BALLERS 0.2.3 — мобильный UX и неон пилота

## Что изменилось
- Чёрный фон, неоновые зелёный / фиолетовый / голубой акценты. Компактный профиль с фото и fallback, ближайший игровой день выше статистики.
- Главная · Игра · Сообщества · Профиль. Мяч после главной: зелёный при «Иду», голубой для приглашения/доступного дня, LIVE при текущем матче. Создание — через плюс сверху.
- Подтверждённая статистика на главной свёрнута. Тестовые показатели не смешиваются с реальной карьерой.
- Один верхний колокольчик. Актуальные уведомления и история разделены. Прочтение запроса не подменяет ответ; подтверждённый капитаном запрос закрывается только для него. Окончательное подтверждение / разрешение теста закрывает остальные запросы. Исправление события создаёт новую ревизию запросов.
- Вкладка «Игра»: ответы на приглашение, раскрывающиеся составы, «Матчи · N», история игровых дней. Личные матчи — из профиля.
- В игровом центре: живой матч и результаты наверху, вспомогательные настройки свёрнуты. События матча раскрываются отдельно.
- Первый матч можно запустить без отдельного сохранения стартовой пары: первые две команды по порядку, при первой ничьей отдыхает первая. Можно заранее изменить пару. Правила и капитаны по-прежнему должны быть сохранены. Новая серверная функция делает выбор пары + старт одной транзакцией.
- «Завершить игровой день»: у организатора в «Игре» и вверху игрового центра. При активном матче закрытие запрещено сервером. Количество матчей заранее не фиксируется. После закрытия неподтверждённые результаты можно подтвердить, но новые матчи запускать нельзя.
- Приветственная карточка: фото, Baller ID, реальные показатели; плавное появление с одним поворотом, автоматическое закрытие через 5 секунд, нажатие сразу пропускает. Не чаще раза в календарный день в этом браузере на аккаунт, только при входе на главную. Отключается в профиле. При reduced-motion заставка не показывается. Приглашения и прямые игровые ссылки не перехватываются.
- Сессия Supabase явно сохраняется и обновляется. Это не отменяет выход из аккаунта, очистку браузера, приватный режим и серверное истечение/отзыв сессии.

## Установка в существующий проект 0.2.2

1. Сохрани резервную копию папки проекта и тестовой БД. Останови локальный сервер (Ctrl+C).
2. В Supabase SQL Editor проверь, что открыт **BALLERS Test**. Выполни **только** `supabase/migrations/20261019_004_mobile_notifications.sql` целиком. Нужны уже установленные 001, 002 и 003. Baseline и старые миграции повторно не запускать. При ошибке остановись: не запускай отдельные куски скрипта.
3. Скопируй содержимое папки из ZIP поверх текущей папки проекта. Не удаляй `.git`, `.env.local` и свои локальные настройки. ZIP их не содержит. В ZIP включены `netlify.toml` и тот же адаптер Netlify 5.16.2.
4. В PowerShell в папке проекта:

```powershell
npm ci
npm run build
npm run dev
```

5. На localhost проверь главную, «Игра», колокольчик, историю, закрытие дня и подтверждение ожидающего результата. Уже закрытый день не должен отображаться как будущий.
6. Останови dev (Ctrl+C), проверь файлы перед отправкой:

```powershell
git status
git add .
git diff --cached --stat
git diff --cached --name-only
```

Если в списке есть `.env.local`, любые настоящие `.env` или ключи — **не делай commit**, сначала убери их из индекса. `.env.example` — только пустой публичный шаблон.

```powershell
git commit -m "BALLERS alpha 0.2.3 mobile UX and notifications"
git push
```

7. Netlify автоматически соберёт main. Дождись Published и проверь https://ballerrs.netlify.app. Менять существующие Supabase URL, publishable key и OAuth callback для этого обновления не нужно. Применение SQL через GitHub / Netlify автоматически не происходит.

## Apple и VK — честные границы релиза

Google работает как прежде. Кнопки не изображают несуществующие способы входа.
- Apple: клиентская поддержка включается `NEXT_PUBLIC_AUTH_APPLE_ENABLED=true` **только после** настройки Apple Developer / Supabase и проверки возврата. Нужны собственные настройки провайдера, которых в архиве нет.
- VK: в установленном Supabase SDK нет встроенного provider `vk`. Подготовлен вход через идентификатор совместимого custom provider: `NEXT_PUBLIC_AUTH_VK_PROVIDER=custom:...`. Его нельзя включать до настройки и проверки отдельной интеграции VK ID. Наличие пользовательских OAuth-провайдеров в конкретном Supabase-проекте/тарифе и протокол VK требуют отдельной проверки. Готовой VK-интеграции релиз не обещает.
- Секретные ключи Apple/VK/Google — только в серверных настройках провайдеров, **никогда** в `NEXT_PUBLIC_*`, ZIP или GitHub.
- Не создавай второй профиль для того же человека ради нового провайдера. Связывание учётных записей требует отдельного безопасного сценария с подтверждением; автоматическое объединение по имени запрещено. Этот релиз не меняет auth identities и не сливает существующие аккаунты.

## Проверки и ограничения

Сборка, линтер, серверные и браузерные проверки описаны в `docs/VALIDATION_0023.md`. Браузерные тесты используют настоящий локальный PostgreSQL/PGlite, но имитируют OAuth и сетевой транспорт. Это не тест живого Supabase, Google, Apple или VK и не гарантия работы во всех браузерах.

Netlify badge не удалён обходным способом: это настройка/условие платформы. Если его можно отключить в доступном тарифе, сделай это штатно. В приложении оставлен запас под нижнюю панель; сам внешний badge код BALLERS не контролирует.

Уведомления в этом релизе — внутри приложения. Системные push и напоминания за 3 дня / сутки / 6 и 2 часа ещё не реализованы. Схемы расстановок, услуги консультантов и аналитический подбор — последующие этапы.
